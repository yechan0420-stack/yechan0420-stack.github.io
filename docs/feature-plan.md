# 기능 계획 — 방명록 (Guestbook)

> 대상 프로젝트: 김예찬 자기소개 홈페이지 (`yechan0420-stack.github.io`)
> 관련 Notion 허브: 김예찬— 홈페이지 프로젝트 기록
> 상태: 설계 확정, 미구현 (이 문서는 명세만 담음)

## 1. 목표

방문자가 이름과 한 줄 메시지를 남기고, 남긴 메시지들이 목록으로 보이는 방명록 기능을
기존 단일 페이지 홈페이지에 섹션 하나로 추가한다. "나를 쉽게 소개하는 홈페이지"라는
프로젝트 목표에 맞춰, 방문자와의 가벼운 상호작용을 더한다.

## 2. 화면 구성 (입력란 · 버튼 · 결과)

기존 `index.html`의 "연락하기" 섹션 아래에 새 `<section id="guestbook">`를 추가한다.

- **입력란**
  - 이름: 텍스트, 필수, 최대 20자
  - 메시지: 텍스트, 필수, 최대 200자
- **버튼**
  - "남기기" (제출). 제출 중에는 비활성화하여 중복 제출을 막는다.
- **결과 영역**
  - 최신 메시지 목록 (이름 · 메시지 · 작성 시각)
  - 최신순 정렬, 최대 50개 표시
  - 상태 표시: 불러오는 중 / 비어 있음 / 불러오기 실패를 구분해 안내

## 3. 저장할 항목 (Supabase 테이블 `guestbook`)

| 컬럼 | 타입 | 제약 / 기본값 | 설명 |
|------|------|---------------|------|
| `id` | uuid | PK, 기본값 `gen_random_uuid()` | 고유 ID |
| `name` | text | not null, 1~20자 | 작성자 이름 |
| `message` | text | not null, 1~200자 | 메시지 본문 |
| `created_at` | timestamptz | 기본값 `now()` | 작성 시각 |

## 4. 성공 / 실패 동작

- **저장 성공**: 입력란 비움 + "메시지를 남겼어요" 안내 + 목록 맨 위에 즉시 반영
- **입력 검증 실패 (빈 값)**: 제출 전 "이름과 메시지를 입력해 주세요", 저장 안 함
- **입력 검증 실패 (길이 초과)**: 입력 단계에서 제한하거나 "글자 수를 줄여 주세요" 안내
- **저장 실패 (네트워크/서버)**: "저장에 실패했어요. 잠시 후 다시 시도해 주세요", 입력값 유지
- **조회 실패**: "메시지를 불러오지 못했어요" 표시 (빈 목록과 구분)

## 5. 데이터 흐름 아키텍처

정적 프런트엔드(브라우저 JS) → Netlify Functions(서버) → Supabase.

- 브라우저는 Supabase를 **직접 호출하지 않고** Netlify Function을 호출한다.
  - 이유: Supabase 키와 검증 로직을 서버에 두어 공개 출력에서 비밀을 분리한다.
- Netlify Function이 Supabase와 통신한다.
  - `GET  /.netlify/functions/guestbook` → 최신 메시지 50개 조회
  - `POST /.netlify/functions/guestbook` → 이름·메시지 저장 (서버에서 길이·빈값 재검증)

## 6. 접근 제한 (자유 입력)

방명록은 로그인 없는 자유 입력이므로 악용 방지가 필요하다.

- **Supabase RLS 활성화** (`guestbook` 테이블)
- 브라우저는 Supabase에 직접 접근하지 않으므로, 쓰기/읽기는 Netlify Function이
  서버 키로 수행한다. `service_role` 키는 **서버 환경변수에만** 두고 프런트에 노출하지 않는다.
- 서버 함수에서 재검증: 이름 1~20자, 메시지 1~200자, 빈 문자열 거부.
- UPDATE/DELETE는 노출하지 않는다 (함수에 해당 엔드포인트를 두지 않음).
- 1차 스팸 방어: 클라이언트 연속 제출 방지(버튼 비활성화) + 서버 길이 제한.

## 7. 가장 작은 완성 버전 (MVP)

기존 단일 `index.html`을 유지하면서 방명록 섹션 1개만 추가한다.
로그인·관리자 삭제·수정 없음. "입력 → 저장 → 조회 → 표시" 한 바퀴를 완성한다.

## 8. 배포 구성 요약 (Netlify)

- 공개(publish) 폴더: 정적 파일만 (`index.html` 등). 서버 함수는 공개 폴더에 복사하지 않는다.
- 서버 함수: `netlify/functions/` (Node.js 런타임, Netlify 클라우드에서 실행)
- 설정: `netlify.toml`
- 공개 출력 제외: `.git`, `.env`, `.kiro`, 개인 기록, `node_modules`, 서버 비밀 코드
- 환경변수(대시보드에만 입력): `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`

## 9. 검사 방법 (테스트 계획)

구현 후 아래 항목을 수동으로 확인한다.

1. 정상 입력(이름+메시지) 제출 → 목록 맨 위에 새 메시지 표시
2. 빈 이름 또는 빈 메시지 제출 → 검증 메시지, 저장 안 됨
3. 길이 초과(이름 21자+/메시지 201자+) → 입력 제한 또는 거부 안내
4. 페이지 새로고침 → Supabase에서 목록이 다시 로드됨 (데이터 영속성 확인)
5. 네트워크 차단 상태에서 제출 → 저장 실패 안내, 입력값 유지
6. 함수 조회 실패 상황 재현 → "불러오지 못했어요" 표시 (빈 목록과 구분)
7. 브라우저 개발자도구 네트워크 탭에서 Supabase 키가 프런트로 노출되지 않는지 확인

## 10. 미해결 / 확인 필요

- Supabase 프로젝트 생성 및 `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` 발급 (사용자 작업)
- 로컬에 Node.js/npm 미설치 → 로컬 함수 테스트(`netlify dev`)는 설치 후에만 가능.
  미설치 상태에서는 Netlify 클라우드 빌드로만 함수가 실행됨.
